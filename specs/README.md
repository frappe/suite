# App Specs

Use `specs/<app>/<NNN>-<slug>.md`, numbered within each app, e.g. `specs/meet/001-recording.md`. Create app directories when the first spec is written.

Start each spec with a title, `Status: proposed | accepted | superseded`, and its scope. Describe observable behavior and constraints; link relevant domain definitions and ADRs rather than duplicating them. Superseded specs link to their replacement.

Read only specs relevant to the task. Proposed specs are not current contracts; accepted specs may still need implementation.
