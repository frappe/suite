New Drive architecture

0Today: what Drive is built on

Drive stores every file, folder, and document as a row in the framework's File table, with seven extra columns bolted on. Sharing is a second table with five yes/no flags per person. Every user has a private folder under Users/. A shared area is the folder Drive.

The tree, as File rows
Drive/                    # shared with everyone (read)
├── Previous Teams/
└── Finance/              # Alice made this
    ├── budget.xlsx
    └── Q3 forecast       # a Sheet, body lives elsewhere
Users/
├── alice@x.com/          # her private space
└── bob@x.com/
Home/                     # framework attachments, not Drive
Sharing, as Drive Permission rows
entity   user        read comment share upload write deny
Finance  bob@x.com    1     1       0     1     0    0
Finance  $GENERAL     1     0       0     0     0    0
Finance  ""           1     0       0     0     0    0  # anyone with link
budget   bob@x.com    1     1       1     1     1    1  # deny = all bits set

To answer "may Bob edit budget.xlsx?", the code walks up the folder chain with a recursive query, then decides flag by flag. Owners bypass everything. Sheets does not use this table at all; it has its own share dialog on the framework's DocShare. Slides serves images through its own endpoint that no permission model can reach.

1Put the path on the row

Decided 2 September, before this map. It is the ground every later decision stands on.

Today
File row
  name     k3v9q2m8xa
  folder   f7a2…          # parent only

# ancestors need a recursive query
# every time, then flag-by-flag merging
Decided
Drive Node row
  name     k3v9q2m8xa
  title    budget.xlsx
  path     /d1x2/f7a2/   # ids of every ancestor

Drive Grant row  # the ONLY permission table
  node       f7a2
  principal  bob@x.com
  role       30           # one number, 0 = deny
# "may Bob edit budget.xlsx?"
ancestors = split(node.path)                  # zero queries
rows = grants WHERE node IN ancestors AND principal IN bob's principals
answer = the row nearest the file wins; role 0 there means no
  • One table for permissions. No cache, no closure table, no recursion.
  • A folder page is three cheap queries. A move is one UPDATE on path.
  • Measured, not argued: the benchmark picked this over two other designs.

3Roots, and what happens when Alice leaves

Ticket: Shared spaces and offboarding model.

Today
Users/alice@x.com/        # a folder like any other
  Finance/                # if she made it in her space

Alice leaves:
  move 40,000 rows somewhere?
  rewrite owner on each?
  owner = full access, always
Decided
Drive Root                # a new small table
  id     kind      user        state
  r01    Shared    -           Active
  r02    Personal  alice@x.com Active
  r03    Personal  bob@x.com   Active

Alice leaves:
  r02.state = Archived      # one field, nothing moves
  Bob keeps exactly the grants he had
  owner grants nothing; access is grants only
  • Business site: one Shared Root plus one Personal Root per user. Personal site: Personal Roots only.
  • Many shared spaces ("Team drives") are out of scope. It rebuilds the team model that was just removed.

4Six roles in a strict ladder

Ticket: Role ladder semantics.

Today
five flags, any combination
  read comment share upload write
Bob on Finance:  1  1  0  1  0
# upload without read is possible
# share without write is possible
# 32 combinations, each a special case
Decided
NONE    0   # stored deny
READ   10   open, download, export
COMMENT 20  + comment
UPLOAD 30   + add children
EDIT   40   + rename, move, trash, change content
MANAGE 50   + share, delete for good

Bob on Finance: 30   # higher contains lower
  • Bob (UPLOAD) adds notes.docx to Finance. He gets one EDIT grant on that file, so he can fix his own upload.
  • Only MANAGE shares. A share link may carry up to EDIT, never MANAGE.
  • Suite Admins bypass everything, in code, as today.
  • Migration table: grants round down, denies round up. upload gains read; share without write is ignored.

5Bytes live only while something names them

Ticket: GC reference discovery mechanism. A framework ask, blocking.

Framework GC today
File Blob  # bytes, keyed by sha256
  ↑ counted only from tabFile.blob

a blob held by a Drive Node alone
  → deleted after 24 h  data loss
Decided
GC asks the metadata:
  every Link field → File Blob, in any doctype
  Drive Node.blob, Drive Node Version.blob, …

one NOT EXISTS per column
unindexed column → include, and warn
discovery fails → delete nothing

6What a product owns, what Drive owns

Ticket: Content app contract. Applies to Writer, Sheets, Slides, and any later app.

Today: Q3 forecast (a Sheet)
Sheet row
  title, trashed, trashed_on   # duplicated
  sheets_data                  # body + comments
  head_snapshot → Sheet Snapshot
DocShare rows                  # its own sharing
File row
  content_doctype = Sheet      # one-way link
  file_name = "Q3 forecast"    # duplicated
Decided
Drive owns, on the node:
  title, place, grants, trash, versions,
  comments, activity, modified time
The app owns:
  the live body, its change log, collab state

Sheet row
  node → Drive Node            # two-way, never changes
  sheets_data                  # body only
one declaration per app: identity, factories,
  bytes, on_purge, satellites
  • An edit owes Drive one touch. Nothing else.
  • Sheets drops DocShare and joins the same engine as everyone.

7Previews and versions

Ticket: Renditions and thumbnails model.

Today
.thumbnails/k3v9q2m8xa.thumbnail   # a sidecar on disk
Writer Version   (Writer only)
Sheet Snapshot   (Sheets only)
exports cached in various places
Decided
Drive Node Preview
  node, source_blob, blob    # one 512 px WebP per node
  same bytes → same preview, reused

Drive Node Version           # one table for every kind
  node, seq, kind (auto|named|milestone),
  label, pinned, actor, size, blob

Exports: streamed on request, never stored
  • Replacing budget.xlsx keeps the old bytes as an auto version.
  • One retention ladder for all: every auto version for 24 h, one per hour to 7 days, one per day to 30, one per week to 90, then gone. Named and pinned stay.

8Publishing is a grant to the Public

Ticket: Publishing capability.

Today
Drive Permission
  entity  user  read
  deck1   ""    1        # "" = anyone, incl. Guest

Slides force-inserts this row on every
save of a composite deck. Nobody chose it.
Decided
Drive Grant
  node   principal  role
  deck1  $PUBLIC    10     # READ, never higher

$PUBLIC is a principal every session holds.
Only MANAGE may write it. No app publishes
for you. A deny nearer the node unpublishes.

9Share links are grants with a secret

Ticket: Link sharing semantics.

Today
one row per node with user = ""
one URL per node: /drive/file/k3v9q2m8xa
no password, no expiry
Drive Token: single-use download links
Decided
Drive Grant
  node   principal              role  password_hash  expires_on
  budget $LINK:7Hq2ZpL9vRt3cW8kQa1b 20    ab12…          2026-12-31

URL: /drive/l/7Hq2ZpL9vRt3cW8kQa1b
many links per node, each its own grant
browser sends X-Drive-Links: token[.ticket]
unlock = HMAC ticket, 30 days, no server state
# resolution, two passes
1. Bob's own principals (email, groups, $GENERAL)
     a deny here is final
2. else: the best of $PUBLIC and any links he holds, nearest wins

10WebDAV rides the same engine

Ticket: WebDAV mapping, amended by Quota policy.

Today
WebDAV has its own storage code
and its own permission checks
(prototype of nearest-wins already lives here)
Decided
mount: the Personal Root only    # one mount
  PROPFIND → READ    PUT → UPLOAD or EDIT
  DELETE   → EDIT    LOCK → EDIT
Q3 forecast appears as Q3 forecast.xlsx, read-only
PUT = one put_blob; every replace makes a version
same SDK calls, same activity rows as the web app

11Quota: a counter on the root

Ticket: Quota policy.

Today
Drive Settings.quota per user (MB)
usage = SUM over the user's files, each time
a Redis lock per owner around every write
folder sizes rolled up on every change
Decided
Drive Root
  quota_bytes   0 = site default for its kind
  used_bytes    # the counter

admission = one statement, the row is the lock:
UPDATE root SET used = used + Δ
 WHERE quota = 0 OR used + Δ <= quota
0 rows → refused

counts: Active + Trashed nodes, versions, reservations
free:   previews, exports, document bodies
daily recompute repairs drift
  • Logical size: two copies of the same bytes in one root pay twice. Dedup saves the site, never the root.
  • An Archived Root pays for itself. No reclaim clock; a Suite Admin purges it on purpose.

12Migration: Build, then Cleanup

Ticket: Migration mapping. Fourteen decisions; the shape is here.

Build (additive, rerunnable)
gate: storage_v2 on, else throw
framework backfill → File.blob        # local files
S3 objects: hash once, copy to framework key
roots   Drive → Shared, Users/<email> → Personal
nodes   same ids, by depth, dedupe titles
grants  5 flags → role; "" → $PUBLIC + $LINK
versions, comments, favourites, recents, activity
quotas, reservations → root
recompute used_bytes; write report.json
Cleanup (one release later)
refuses unless every File row has a node
        and GC discovery (decision 5) exists
deletes Drive's File rows, 7 custom fields
drops Drive Permission, Token, old activity log
DocShare rows, Writer Version, Sheet Snapshot
deletes Drive's old S3 prefix
never deletes local files (blobs point at them)
rollback after this: database restore only
# Bob's favourite on budget.xlsx, before and after
 Drive Favourite
   user    bob@x.com
-  entity  k3v9q2m8xa   # → File
+  node    k3v9q2m8xa   # → Drive Node, same value
  • Side tables reshaped: Drive Activity, Drive Recent, Drive Favourite, and Drive Notification as a pointer at an activity row.
  • Sites that run Drive on S3: objects are copied into the framework layout; storage doubles until Cleanup.
  • One storage location in the end: a framework job relocate_blobs() moves legacy local attachments to the configured driver after Build. Drive moves no bytes.
